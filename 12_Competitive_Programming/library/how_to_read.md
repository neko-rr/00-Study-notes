## 読む順番（おすすめ）

```text
1. 問題名と「何を出力するか」（最後の段落・出力欄）
2. 入力形式（何行で何が来るか）
3. 制約（N の最大が最重要）
4. 問題文のルール（操作・条件）
5. 入出力例（手で追う）
```

「最初から全文を丁寧に」より、**出力と制約を先に見る**方が速いです。

---

## 1. まず「何を出力するか」

| よくある出力 | 意味 |
|---|---|
| 整数1つ | 答えの数・回数・最大値など |
| `Yes` / `No` | 判定問題（大文字小文字に注意） |
| 空白区切りの列 | 構成した数列・順列など |
| 複数行 | クエリごと／グリッドなど |

出力欄に書いてある文字列を、**そのまま**出す（`YES` なのに `Yes` で WA、が典型）。

---

## 2. 入力形式を図にする

```text
【入力例】
3 2
1 2 3
```

自分用メモの例:

```text
1行目: N M
2行目: A1 A2 ... AN
```

コードに落とす:

```python
N, M = map(int, input().split())
A = list(map(int, input().split()))
```

複数テストケースなら「最初に T」があるかも確認。

---

## 3. 制約で解法の上限を決める

| 制約の例 | 考えてよい計算量の目安 |
|---|---|
| `N ≤ 10` | 順列全探索など重い全探索 |
| `N ≤ 100` | `O(N^3)` まで視野 |
| `N ≤ 10^4` | `O(N^2)` は危険なこと多い |
| `N ≤ 10^5` | `O(N log N)` か `O(N)` |
| `N ≤ 10^6` | `O(N)` 基本、入力も高速化 |

詳しくは → [complexity.md](complexity.md)

**B/C帯の感覚**: A〜C はだいたい全探索・実装・簡単な数学で足りることが多い。  
制約が `10^5` なのに二重ループしていたら、型が違う可能性大。

## 4. 問題文で拾うキーワード

| 言葉 | 疑う型 |
|---|---|
| 最大・最小 | 全探索／貪欲／二分探索 |
| 何通り | 数え上げ・場合分け・mod |
| できるか | Yes/No・判定を関数化 |
| マス・グリッド | → [grid_intro.md](grid_intro.md) |
| 操作を繰り返す | シミュレーション |
| 並べ替える | ソート |

## 5. 入出力例の使い方

1. **入力を紙に書く**  
2. 自分の理解で答えを出す  
3. 出力例と一致するか確認  
4. 一致したら、コードでも同じ入力を流す  

```text
【入力例】
2 3
【出力例】
5
```

「なぜ5か」を一言で言えるまで実装しない、が安全です。

---

## 6. 変数の意味をメモする

| 問題の言葉 | 自分の変数 |
|---|---|
| 人数 | `N` |
| クエリ数 | `Q` |
| i 番目の値 | `A[i]`（0-indexなら `A[i-1]`） |

問題が **1-index** でも、実装は **0-index** にそろえる人が多いです。

```python
# 問題: 1-index の A_i
# 実装:
A = list(map(int, input().split()))  # A[0] が A_1
```

## よくある読み落とし

| 読み落とし | 結果 |
|---|---|
| 「以上」「以下」「未満」 | 境界で WA |
| 「1 以上 N 以下」なのに 0 を含む | WA |
| 複数テストケースの初期化 | WA |
| 出力の空白・改行 | WA |
| 制約の最大を見ていない | TLE |
