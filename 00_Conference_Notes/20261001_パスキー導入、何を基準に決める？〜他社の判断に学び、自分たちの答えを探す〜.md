# パスキー導入が求められる背景とマルチテナントSaaSでの意思決定	株式会社SmartHR 小林 悟朗
- 情シス向けのサービス
- 認証を取り巻く4つの課題
  - パスワード認証の限界
    - 弱いパスワードを作ってしまう
    - 同じパスワードを使いまわしてしまう
    - フィッシングサイトにパスワードを入力してしまう
  - パスワードマネージャーの効果と限界
    - メリット
    - デメリット
      - ドメイン変わる所では、結局手動入力
  - 2要素認証（OTP）の欠点
    - 最大の弱点は、フィッシング耐性のなさ
      - リアルタイムフィッシング
  - デバイス認証
    - デバイスの認証で入る。
    - 強力だが、デバイスを失くすと終わる
- パスキーの仕組
  - 核心：公開鍵認証方式
  - パスキー＝デバイス認証の発展形
    - 技術的には、デバイス認証の延長
      - FIDO2クレデンシャルに、ドメインやユーザーアカウント情報をセットしたもの
    - デバイス認証と異なる点
      - デバイス失くしても、最大の特徴は端末間の動機。プロバイダのアカウントがあれば復旧できる
      - 生体情報：端末のセキュリティチップ内に保管され外部に取り出せない
- マルチテナントSaaS特有の論点
  - Relying Party ID
    - WebAuthnにおいて、登録・認証を行うサービスを表す識別子
  - 論点
    - RP IDを何処に設定するか
      - 検討した案：サブドメイン単位
      - 採用した案：ルートドメイン
    - 意思決定
      - smarthr.jpをRP IDに採用
      - テナントに縛られず、アカウントに紐づくデータとしてパスキーを扱いたかった
      - ユーザーは複数テナントを登録する手間が省ける
    - トレードオフ
      - テナント分離をアプリ側で担保する
      - Discoverable Credentialsの挙動
        - Discoverable Credentials：ユーザー識別子を事前入力せずログインできる仕組
        - 所属していないテナントのログイン画面でも予測が出て来る
- ログイン体験の設計
  - Conditional UI
    - オートフィルで提案
  - 専用ボタン
    - パスキーでログイン
      - Conditional UIが使えない環境でも確実にログイン
- 登録できるパスキーの設計
  - 会社端末・個人端末を使い分けるユーザーがいる⇒複数のパスキー登録に対応
    - 現実的な利用数を踏まえ、15件まで
  - 登録名は～
- Q&A
  - パスキー紛失のリカバリーはiパスでフォローしている
# ログイン成功率を上げるためのパスキー設計・実装 (仮)	株式会社メドレー 宋理央
- 新卒で日本IBM入社
- 2023年から㈱メドレー
- サービス
  - ジョブメドレー
    - ヘルスケア領域向けのオンライン動画研修サービス
    - 公共PCで皆が同じパスワードで利用している事があるのが特徴
- ログイン率を上げたい！
  - ID・パスワード忘れた
  - 機種変更で詰まる
  - 共有PCで保存できない
- 解決：パスキーの導入
  - 端末にパスキーを登録しておけば、ID/PWが分からなくてもログインできる
  - 共有PCで保存できない⇒自分のスマホで登録しとけば、覚える必要がない
- ログイン成功率を上げるために考えた2つの観点
  - ログインのハードルを下げる
  - ログインを失敗・フォローをする
- 工夫
  - ユーザーに入力させない
    - usernameless方式を採用⇒パスキーをDiscoverable Credentialにする必要がある
  - Web・iOS・Androidで同じパスキーを使う
    - 共通IR ID
  - PCではQRコードを表示し、スマホで登録する
    - 共有PC対策
- パスキーは、2種類のログイン方法があり、Discoverable CredentialとNon-Discoverable Credential
  - コードがスライドにあり
- 失敗フォロー
  - residentKeyの設定ごとの違い
    - 感想：もうスライド見よう！分からない
  - preferredでは不十分
  - パスキー対象外であることを伝える
    - 端末の状態を事前にチェックして、パスキー対象外である事を伝える
      - OSバージョン
        - iOS15以下
      - ボタン押すときに判定して、対象外に説明
      - 失敗時にネクストアクションを提示
- 現在、導入から4か月
  - パスキー登録者数
    - 約4.3万人
  - ID/PWのログイン⇒パスキーログインの試行内の成功率
    - Web71.9%⇒98％
