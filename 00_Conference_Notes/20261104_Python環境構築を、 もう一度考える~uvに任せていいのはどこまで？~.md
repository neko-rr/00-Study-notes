# 内容
#### uvが出来る前
- Windows型
  - Pythonの管理マネージャーがバージョン切り替えしてくれる
- Python処理系を取りそろえる
  - major(3).～
- Pythonが入った後は、仮想環境
  - Windows
    - venvモジュール
      - Python処理系にバンドルされる
    - 仮想環境を有効化
- Pythonのサードパーティパッケージ
  - サードバーティパッケージのインストール
  - pip
    - パッケージマネージャのCLI（但し機能は弱い）
  - python -m
    - モジュールをスクリプトとして実行（importせずにCLIを使用する）
    - ハマりにくくなるから、話者は使う
- 仮想環境とは、ディレクトリで出来ている
  - 仮想環境を使わないとしたら、インストール先は1箇所
  - ディレクトリの説明
    - .venv/bin/python
      - 有効化すると環境変数のPATHが見つかるようにしている
- 仮想環境は、常に必要でした
  - 仮想環境は、名前を変えると壊れます
  - 仮想環境は、使い捨て
- バージョン違いが共有するための仮想環境
- パッケージマネージャーわ自分達
  - 仮想環境を理解して使う時代が長かった
#### uvが出来た後
- uv（2024～）
  - Astralという会社が提案（3月にOpenAIが買収）
  - 最初はRustで開発
- uv sync
  - Pythonを見つける（ない場合は、ダウンロード）
  - ロックファイル
- uvが仮想環境を有効にしてコマンド実行
  - 自動で有効化してくれる
- 仮想環境はuvにお任せ
  - 依存の追加
- uvはPythonも管理できる
- 既存の仮想環境とも仲良くやってくれる
- 使う中で、仮想環境をおかしくしてしまったら、.venvを削除
  - すぐに復活できる
- PyPｌにあるCLIツール
  - CLIツールを仮想環境を意識せずに使えます
  - uvx
    - uvが一時的な仮想環境を作成
    - そこにCLIツールをインストールして実行
  - uv tool install
    - llmが入った仮想環境ができる
- スクリプトと別に仮想環境を用意していたが
  - PEP723-inline script metadata
- uvに任せる範囲
  - CLI管理やパッケージ管理も任せれる
- サプライチェーン攻撃
  - 例：LiteLLM
  - eMudhra証明書
  - 結果：可能な限りバージョンを上げましょう！
- uvは、仮想環境を「正しく早く使えるツール」
