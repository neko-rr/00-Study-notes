# 12:05-12:12	マルチプロダクトのセキュリティを「標準化」で底上げする	㈱estie リードエンジニア Masaki Miyazakiさん
- 不動産のマルチプロダクトを提供している
  - 商業用不動産
- 構成が同じなら防御方法も同じであるはず
  - しかし実際には、BFFのミドルウェアを各プロダクトに独自実装があり、課題感
- Webアプリの防御策は、公知のもので、プロダクト固有の判断もAIが可能
- 方針：無関心でいられない状態を作る
  - １：文書で組織のスタンスを明示する
    - 例：入口検証、
    - プロダクト立ち上げ時に標準文書を読むか？
      - 標準文書があると知っていても、コピペしても立ち上げ時に読む人は少ない
      - どんどん進む内に分岐していく
  - ２：ライブラリを作る
    - 標準の内、個別判断不要なものは、差し替え口を設けず完全に固定する
    - コピペするのは、呼び出しの数行だけ
  - コピペで済まない部分が標準への導線に
    - ライブラリを作成する事により、関心を持った開発者が標準ドキュメントを本当に読むようになった
- 文書：後から来た人も再判断できるように判断の材料を残す
- ライブラリ：個別判断不要な箇所は固定
  - そうでない部分は、～

# 12:23-12:30	生成AI活用にブレーキをかけない — シャドーAI時代のブラウザセキュリティ
- 会社が把握していないAI、業務で使った事はありませんか？
  - 68％（解析結果）
- 動機は悪意からではなく、「仕事を速く終わらせたい」という善意からのため、根絶が難しい
- なぜ駄目か
  - 入力された瞬間から、そのデータは会社の統制の外に出る
  - セキュリティ専門家の半数もやってしまう
  - IPAのセキュリティ3位に初登場
- 「前面禁止」しても解決しない
  - 個人のスマホでやるだけ
  - むしろ、会社から見えにくくなり危険
- 85％超
  - 日常業務は、ブラウザ経由
- 危ない操作は、ブラウザの中で起きる
  - 機密データをAIへ貼り付け
  - 偽サイトへパスワード入力
  - 操作が起きる場所＝ブラウザで守るのが最短
- ブレーキをかけない対策
  - 見える化
    - アンケートではなくて、ログで実体を把握
  - 制御
    - 前面ブロックではなく、リスク行動だけ止める
  - 誘導
    - 会社公認AIに誘導
- 実装例
  - Chrome Enterprise Premium
    - 管理側
      - ログえ実態を把握できる
      - エージェントレスで簡単
    - 使用側
      - いつものブラウザ
      - AI使用可能
