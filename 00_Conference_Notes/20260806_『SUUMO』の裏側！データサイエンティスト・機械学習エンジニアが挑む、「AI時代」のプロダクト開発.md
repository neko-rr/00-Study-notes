# SUMOにおける画像生成の活用
- 今年から注文・カウンター領域のMLE業務に従事
- SUMOおうちメーカー
  - 注文住宅検討ユーザーの「漠然とした理想」の言語化・可視化を助けるプロダクト
  - 今、立ち上げ期でプロダクト磨き中
- カウンター店舗での接客版とアプリ版
  - カウンター店舗
    - 接客カバーがあるので、時間かかってもよくて品質重視
    - 枚数少ない
  - アプリ版
    - 時間短く
    - スケールできる必要がある
- MLLM：マルチモーダル
  - 接客版
    - 要望ヒアリング⇒要望抽出プロンプト生成（MLLM）⇒
- 課題１：画像生成商用プロダクトは高性能だが
  - 高コスト
  - 低速
  - 不安定
  - 意外と苦手な部分：細部の修正が反映されづらい
    - 現実的にあり得ない画像
    - 複数画像間の整合がとれない
- グリッドレイアウト出力により
  - リクエスト回数を1/6に
  - 6案を1回で生成して、後処理で切り分ける
    - 外観3案＋LDK内観3案
  - 差分強調や画像整合性が取れる副産物あり
- 高速なオープンウェイトモデルの利用で10倍高速化
  - 商用APIは1回の画像編集に数十秒＋高負荷時のレートリミット（429）
  - セルフホスト
- GPU選定
  - 速度要件を満たす候補の中から、コストと確保のしやすさで決める
- 商用モデルとオープンウェイトモデルの使い分け
  - オープンウェイトモデルは高速だが、条件次第で崩れやすい
    - 小さい対象、画面端、特定の色、複数指示
- 事前生成とリアルタイム生成の使い分け
  - 軸１：コスト・速度面
    - 数が有限なら事前生成しておき、すぐに返却するのが最速かつ最安
  - 軸２：品質（苦手への対応）
    - 事前検証で破綻しやすい部分を見極め、破綻しやすい部分は事前生成に寄せる
  - テキスト分析を挟み、ユーザーの危険プロンプトを弾く
    - 電気ねずみとか
# 音声データのリアルタイム要約による「スーモカウンター」の
- 新卒3年目
- スーモカウンター
  - 新築マンション向け
  - アドバイザーがカスタマーに伴走する相談サービス
- 施策対象
  - 接客の合間に行う接客方針の壁打ちを行う
    - 接客担当者⇒ベテラン社員
- 施策背景
  - 時間が限られている
    - 情報共有に半分の時間が割かれる
  - 口頭での情報共有に限界がある
    - 伝え漏れ
    - 忘れ
- 施策概要
  - ヒアリング中にAIが要約して、待機しているベテラン社員に情報共有
    - ベテラン社員が既に内容知っているので、方針のみ話せる
- 30秒に1回Vertex AI Geminiで要約
  - Zoom RTMS
    - エージェント噛まさずに可能
    - 会議を検知して要約開始
    - 精度：地名が若干苦手
  - 要約生成方法
    - チャンク3個を並列処理
      - 実行時間が10分の1になった
  - 要約ロジック
    - ハイパフォーマンス社員の思考体系を形式知化し、プロンプトに落とし込んだ
      - 暗黙知⇒形式知⇒プロンプト
      - 実際に接客担当からのフィードバックをもらって対応
    - 磨き込みの高速化
      - 開発者1人でできるようにし、即時反映
      - インフラ・画面・要約ロジック改善⇒フィードバック
      - 特にはじめの内は、使用している様子を後ろから見て、質問もしていた
        - それからも週1でヒアリング
      - 店舗は、かなり忙しいので、ヒアリングは、そこもコツ
- 暫定の検証結果
  - 一部チームでF/Sを実施し、成約率が改善傾向
- 今後は、全国展開を実施したい
