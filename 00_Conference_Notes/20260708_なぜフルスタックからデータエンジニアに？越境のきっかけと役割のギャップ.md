# データエンジニアになって良かったこと・大変だったこと
- 大変だった事
- 萩原
  - 広い目で見なければいけない
    - 上流システムの仕様が予告なく変わる
  - 閉じた世界
- 六車
  - ほぼ同じ
  - 上流サイレントは、データエンジニアあるある
    - アプリ側の開発がどんどん進んで、スキーマがサイレントに変わって、いきなりタイムラインが失敗する
  - 「なんかやりたい。データ利活用したい」という曖昧な要望を出す人に向き合う：泥臭い
- 良かったこと
- 六車
  - 自分がやった事が、じんわりと色んな所に良い作用を及ぼすのが良い
    - 意思決定に使用するためのダッシュボードとか
- 萩原
  - 日々、向いていないなと思いながらやっている
  - 但し、これからの時代は良い分野だと思う
    - AIに食わせるデータを整える
# データエンジニアに興味がある人は、まず何をしたら良い？
- 六車
  - 機会があまりない
    - 大手レベル
    - しかも、既にデータ基盤が作られているから、そこに入っていくのが難しい
  - AIに業務で何をするか質問する
    - 何をするかは、分かるようになる
    - 勉強は、教科書等で体系的に学ぶのが良い
- 萩原
  - フルスタックエンジニアの経験が凄く活きていると考えている
  - 個人でも無料でも無料APIで実際に出来るので、そういう経験をするのもあり
    - 自分のデータを取る所から始める
# Q&A
- 六車
  - なぜ新卒1年目でDEに転職したの？
    - CI/CDとか楽しくて、若いから思いっきりが良かったのもある
- DBエンジニアとデータエンジニアの違いは？
  - 萩原
    - 何かのDBに特化する人と全社的なデータを保守運用する人という違いの認識
  - 六車
    - 同じ
- 全く集約されていないので、時間が掛かり、焦りばかりが募ります
  - 六車
    - スモールスタート。で、大きくしていく。
      - ちょっとした、Excelでも手作業でも良いので、綺麗なデータを集めて、それをAIに参照させて、一部の人に試してもらって成功体験を積む
      - その裏で、大きい準備をする。
      - 経営層向けの準備をする
  - 萩原
    - 同じ
- データエンジニアとして成長していくためにどんな要素を伸ばしていくか
  - 萩原
    - データを右から左に動かしていく：元データ⇒加工⇒BI
      - 一番左が間違っていると全部間違うので、神経質なくらいに入口でデータを確認するマメさが必要
        - 信用にも繋がるし、全部やり直しになるし、重要。間違いに気付かないと経営判断ミスにも繋がる
- 六車
  - 上記に共感
  - 人を愛せるか
    - 思っているよりもデータエンジニアって、ステークホルダーが多い
