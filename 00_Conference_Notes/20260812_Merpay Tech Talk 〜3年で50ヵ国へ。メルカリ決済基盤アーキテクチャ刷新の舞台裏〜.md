- 50か国に向けての課題
  - PSP接続が本体と密結合
    - 決済手段を1つ増やすだけで、決済のコアロジックに手を入れる事になる
    - 国が増えるほど変更範囲と影響調査が膨らみ、展開スピードが頭打ちに
  - 残高と会計がバラバラ
    - 1回の決済で書き込みが3つに分かれる：途中で失敗するとズレる
      - お客様残高
      - メルカリ売上
      - 会計イベント
    - ズレを防ぐSagaの実装は作り込みが重く、通過・国・PSPの組み合わせが増えるほど複雑さが膨らむ
- 2つの解決策
  - PSP接続の分離
    - Payment Provider Serviceに分離
      - PSP固有のAPI呼び出しやWebhook処理を、サービス側に閉じ込めた
      - PSPや決済手段を追加しても、Payment Serviceには手を入れない
  - 複式簿記による整合性
    - 残高と会計をペアで記録
    - 構造的にズレようがない
- 台湾・USで稼働中
  - 次は、国内メルカリへの還元目標
# パネルディスカッション
- プロジェクト規模と進め方
  - 丁度ローンチの1年前からプロジェクトが始まった
  - 決済チームは、4つに分けた
    - それぞれ3～5人くらい
- 大変だった事について
  - 最初は、AIも無かったから、全システムを人が見て、何が必要かを判断していった
    - 影響範囲が特定出来ないからこそ、周りを巻き込めた
    - 最後の方でAIが出てきて、QAは楽になった
- 展開国毎に細かい違いとかあるんですか？
  - 本当に様々ある
  - ある国でだけ不具合が起きたり、クレジットカードに慣れていない国があったり
  - メルカリグループは、全世界に居るので、テストや翻訳をネイティブの現地の人に連絡とって、やってもらったりしている
- 他のプロジェクトとconflictしないの？
  - 既存機能に手を入れる時は、細かくマージして検証していった
- 自由度決めるのが難しい
- 仕組みでAIの安全性を上げていくのが今後の課題
