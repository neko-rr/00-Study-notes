# 内容
- 話者
  - 2025年4月入社　中央省庁のペネトレーションテスト支援を推進
- 個人の見解であり、所属組織を代表するものではありません
- 「AIで脆弱性が増えている」をデータに基づき、一歩深く捉え直せる
- 危険の”総量”は増えている
  - 1件当たりの危険度は増えていない
- 総量
  - 公開CVEは、2023年　約29.066件⇒2025年約48,185件（AIが使われ出したのは2025年後半から）
  - 発見の爆発は、もう肌感覚で分かる
    - パッチチューズデーの規模は、この1年で桁が変わっている
      - ～2026年80件　、現在1月で100件超え
  - 増やしているのは、攻撃側だけではない
    - 増加の主因は、防御側AIによる脆弱性発見の産業化である
    - 社内のセキュリティスキャンの結果、防御側のAIで見つけている
- 「悪用された」の4段階
  - PoC公開⇒武器化⇒in-the-wildで悪用⇒KEV登録
    - in-the-wildで悪用：実環境で攻撃に使われたと報告された状態
      - あくまで観測・報告ベースの事実
    - KEV登録
      - 悪用されたと検証された
- KEVの性質と限界
  - どのKEVも「既知・観測・報告された」悪用の下限値である
    - CVE件数
    - CISA KEV
- 分母と分子を、同じ画面で比較
  - 総量は増えている
  - 悪用に至る割合は、およそ１～２％で横ばいである
    - 横ばいは今の観測であって、将来の保証ではない
- なぜ”率”を見ているのか？
  - 率は量の物差しではなく、増加の原因を切り分ける道具である
  - もし”攻撃能力”側が原因なら、もし”発見”側が原因ならば
- 私見：この割合は、この先　上がると考える
  - 悪用が困難だった脆弱性が、実用的な悪用に変わる
  - 攻撃側全体の技術力が底上げされる
- では、本当に変わったのは何か？
  - 偏り：構成比が跳ねた
    - 脆弱性悪用を入口とした侵害のうち、エッジ機器・VPNが標的だった割合22％
      - 理由：入られてしまえば、対応できない企業が多いため。コロナ禍で利用が増えたため
      - 別組織のソースでも、同じ方向を指している
  - 速さ
    - 悪用の前倒しが増えている
      - 悪用は、パッチより先に到来しつつある
      - ゼロデイ攻撃・n-dayを含む
- なぜエッジなのか？
  - エッジ機器は、EDRの届かない場所に置かれている
  - インターネットに露出
  - 取れた時のリターンが大きい
- これからの守り方と優先順位付け
  - ”速くパッチ”だけでは救えない
    - エッジ機器の脆弱性の完全修正率：54％⇒半数近くが未修正のまま残る
    - 修正までの日数（中央値）：３２日
- 打ち手１：n-day－パッチが存在するもの（従来通り、変わらない）
- 打ち手２：zero-day
  - 露出の最小化：管理画面・Web　UIをインターネットに晒さない
  - 補償統制：多要素認証、ネットワークセグメンテーション、不要機能・不要アカウントの無効化
  - 装置側の検知：証明書の監視、ファイル整合性の確認。ログ分析
- 優先順位の道具立て
  - KEV x EPSS x 露出
  - 全体は見られない。3つの掛け算で対象を少数に絞る
- 大量パッチ時代の運用は、人手では破綻する
  - 月400～600件は、人手による月次レビューの設計限界を超えている
