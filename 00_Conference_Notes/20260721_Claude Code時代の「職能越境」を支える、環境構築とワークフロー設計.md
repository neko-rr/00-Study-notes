# ドキュメント駆動（DocDD）で失敗して見えてきたAI時代のアジャイルにおける2つのキーワード	田上 将吾 氏
- PM、デザイナー、エンジニア含めて9名のチーム
- 1Sprint（2週間）
  - ドキュメント
- 質の高いAI駆動開発PJにおいて重要な考え方
  - 境界付けられたコンテキスト
  - シフトレフト
- ここに至るまでの失敗
  - 仕様駆動開発
    - 更新漏れ・不整合が発生
    - 非エンジニアが参照・レビューしづらい
  - プロセス高速化と認識のずれ拡大
  - 手戻りが発生した
- 厳密な仕様駆動開発から軽量ドキュメントに変更
  - 理由：ドキュメント堅めないと実装できないのは、不都合
- AIとの境界を区切って、高速化
  - 決定論的に決める
- ユーザーストーリーに分解して、スプリントの2・3日目にAIの補助で設計を完了
  - 広義のシフトレフトと呼んでいる
  - 開発初期に全員で合意⇒手戻り減少
  - AIの実装のブレも減った
