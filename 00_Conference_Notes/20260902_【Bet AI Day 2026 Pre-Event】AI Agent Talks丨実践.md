# プロダクトのためのAIエージェント開発・運用の実践
- 個別の課題解決をユーザーワークフローでAIが動いて解決する
  - AIワークフォース
  - お客様：DS/FDEが要望を掘り下げていく
  - プラットフォームとして、汎用品を作らないといけないのが難しい
    - いつもの話
  - 課金体制が難しい
    - ユーザーがログインしないのがベスト
    - 従業課金になると思う
      - あまりLLMを使いたくない（コスト）
        - これをどう抑えていくかが、AIエンジニアとして難しい
      - ユーザーは、自動化したいのに、こんだけかかるならば、辞めとこうとなるので、そういう意味でもコストを下げたい
    - コストの下げ方
      - 評価基盤を作る
        - どの精度ならば、OKかを決める
          - モデルをどんどん安いのにする
          - 新しいモデルが出ると試す
        - バックオフィスの仕事は、細分化していくと、簡単な仕事ばかりなので、モデルもそんなに良いのが要らない
        - 攻め方：モデルが新しくなって、賢く安くなった分、別の自動化を入れる
        - 最初は、コスト高めでスタートして、試していく。
          - その内にドンドン安くなるから。最初からガンガン攻める
        - ここ最近で、3割LLMコストが落ちている
          - しかも、タスク成功率が上がりつつ
        - PoCで最初、ヒアリングに充てる必要があり、最初はコストかけても動く
    - FDEが、FD単位でモデルを最適化して、コストと精度を管理するから、大変
      - 回路作る側のサポートは、プラットフォーム側が担う必要があるから、2段
    - かなりお客様毎に抱えている問題が異なる＆育成方法や精度も異なる
      - だから、共通評価がない
    - 合成データは、FDEがタスク単位でやってはいるが、横展開できない
    - モデルが出た時、モデル変更難しい
      - モデルに合わせて、ワークフローとかプロンプトも色々変更検討をする
      - 今までワークフローでやっていたのを丸投げすれば、できるのでは？
        - 現実は、そんなに単純ではない
          - ステップが動的に決まる
            - AIが一回迷うと、かなりコストが掛かる
            - 迷わないように工夫は、する
          - ワークフローは、静的に決まるので、かかるコストが読みやすい
            - コストが一定というのは、お客様にとっても嬉しい事が多いので、何処を動的にするかは、悩む
    - 業務として、個人を越えて、他者の確認が必要な業務とかでは、静的に組んでいる方が嬉しい事が多い
    - 代行
      - 自分の代わりにやってほしい
      - 他社に頼むのでもロボットに頼むのでも
      - 依頼者の権限の範囲内
      - これは、バクラクと同じで、権限をそのまま渡せばOK
    - 依頼
      - 上司に依頼したり、他部署に依頼したり
        - 業務を推進する上で、自分の権限がないから依頼する行為
      - これに属する業務を上手く表現するのが、かなりムズイ
        - 愚直に入れるのは、かなり難しい
        - 人間世界だと、依頼しても全部OKな訳ではない
          - これをAIにすると、全部OKのただの穴になってしまう
        - 権限昇格できる承認できる人は、誰に移る
          - 結局、穴に戻る
    - FDEもユーザーと考えた時に、デバックしたい・かかった時間を教えて
      - これは、プラットフォーム側には欲しいが、ユーザーは求めていない
      - こういうのは、画面に反映するか、AIだけに留めるかの話になる
- バクラクは上記の逆で、深くドメインに食い込んでいく
  - 前だと、シート課金
  - AIは、従業課金でプラス機能
  - バクラクの評価基準は、各プロダクトチームの中で、頑張ってそれぞれ評価基準を作るという動き
    - 話者的（機械学習）には、簡単に評価基準を立ち上げる基盤を作りたいが難しい
      - 現在は、知見を提供するだけで留まる
        - 合成データセットの良い作り方
          - こだわっているのは、どれだけ難しいタスクが作れるか
            - 普通に作らすと、そのAIが解ける問題しか出してこない
          - 前回のFable5と別モデルの話
          - 批判的ゲートをもう1個作る
    - モデルが出た時、モデル変更難しい
      - 契約管理とかでも難しい
      - モデルに合わせて、ハーネスを変更する必要がある
        - 逆にハーネスを外してあげた方が、ドーンと精度上がったり
      - 細かくタスクを切っていた所を一括にした方が精度が上がったり
    - 権限は難しい
      - ユーザーのロールの範囲内で情報を取得可能としている
        - 但し、統計値とかだと、少なく見られて返って来るとかが起こる
        - 最近だと、タスクに権限を付与するという考えもあるが、今はかなり保守的に倒しています
      - 権限昇格をAIにさせるも検討したが、どこまで行っても100％にならない
        - 100％にならないと＝セキュリティホール
    - ユーザーから見たら、失敗した申請なんて、見たくない
      - だから、保存していない
        - 間違いを判定するために、それを人力回収する事から始めた
      - 今まで、人間がやった事は、ある程度正しい前提なので、「修正体験」を考える事が無かった
        - AIは、修正が前提なので、考える必要がある
      - ユーザーがAIの出力を、何でそうなっているかをすぐに理解できる構成にする必要がある
        - 抽出先に一瞬でハイライト表示
        - これが出来ていないと、確認時間を考えたら手動申請するわ！になってしまう
      - 今まで、OCRで起こっていた事が、AIの活用幅が広がった故にあちこちに発生している
        - しかも、全部を確認できるようにしたら、文字だらけになる
          - シンプルなUIにする必要がある
        - 重みづけして考える必要がある
      - フォームは、人が入力する必要がなくなっている
        - しかし、現在はAIが使えない時に人間が手動登録できる道を残す必要がある
          - 業務が止まってしまうので
        - だから、開発する量が増えたなという印象
      - その計測とかは、バクラクだと、ユーザーも出来る必要がある
        - 今の時代は、ユーザーがAIをカスタマイズ出来るので、ユーザー自身で確認したいという要望がある
          - なので、機械学習エンジニアが今まで見ていた数値をお客様も見たがる
            - 見やすいUIを拘った
            - finとかがそう。バクラクでも提供したい（昔の回答と一致しているか）
          - バクラクでは、その計測を見る必要が無いように、できるだけセットアップされたカスタマイズを提供して、ユーザーカスタマイズを減らしていきたい
